# 电视上怎么看（APTV 订阅接入）

给完全不想碰命令行的人看的版本。原理只有一句：
**电脑上开一个小网页服务，把生成的频道表放在家里网段里，Apple TV 用这个地址去取。**
整个过程不出互联网，不做端口映射，关掉窗口就停了。

> 已经订上了、要按顺序确认哪步通哪步不通 → 看 **[`真机验收单.md`](真机验收单.md)**：
> 六步、每步写清「该看到什么」和「不像的话说明什么」，电视边上拿手机看那一页就够。

---

## 三步

**第 1 步：双击项目根目录的启动器**

- Windows：`启动电视订阅服务.bat`
- Mac：`启动电视订阅服务.command`（第一次双击会被 Gatekeeper 拦住，右键 → 打开）

窗口里会出现这样的内容（下面是 2026-09-22 晚上照当前 `data/output/` 里那一批表重跑一遍抄的，
所以那两个台数和那个时间是**那一次**的；你看到的以你自己的窗口为准）：

```
==============================================================
  APTV 局域网订阅服务
==============================================================
  现在发的这两张表是 09-21 21:18 生成的那一批。
  http://192.168.31.87:8787/hunan.m3u   # 湖南本地优先（39 个台）
  http://192.168.31.87:8787/aptv.m3u   # 全量：央视 + 卫视 + 湖南（98 个台）

  主地址在 APTV 里加不上时，再试下面这几个诊断用的表：
    http://192.168.31.87:8787/probe-pack.m3u   # 试播包：每个流主机族挑一条，逐个点开，回报能动哪几个（17 个台）
    http://192.168.31.87:8787/hunan-lean.m3u   # 同一张表去掉台标和 EPG —— 主地址加不上时试它（39 个台）
    http://192.168.31.87:8787/test.m3u   # 只有几个台的极小表 —— 判断是不是表太大/太复杂（4 个台）

  防火墙状态：已关闭，不会拦电视
  先别做端口映射，这个服务只在家里用。
  窗口别关。电视来取数据时这里会跳出一行 IP。
==============================================================
```

上面那些「（N 个台）」和那句生成时间，都是**窗口打开时现读的**：服务发的就是磁盘上那一份文件，
磁盘上的表换了版，重载一下网页（或重开窗口）数字就跟着换。它只是告诉你「你现在订的是哪一批线路」，
不代表这批线路刚刚被重新测过。

**后面两步里出现的 IP，一律以这个窗口打印的为准**，不要照抄本文档往下写死过的那个数字
（电脑换网络、换 Wi-Fi 都会变）。

**这个窗口不能关**，关了电视就订阅不上。以后每次看电视前都要先双击它一次
（除非已经把服务搬到 NAS 上常驻，那是 P4 的事）。

**第 2 步：先用手机确认网络是通的**

手机连家里 Wi-Fi（必须是电视用的同一个 Wi-Fi），Safari 打开
`http://<窗口里的那个IP>:8787/`

看到「✅ 服务已经起来了」这个页面，才继续往下做。这一步是分水岭，
能一下子把问题分成「网络不通」和「App 不接受」两类。

**第 3 步：APTV 里添加订阅**

APTV → 添加订阅 / 播放列表 → 输入网址，填：

```
http://<窗口里的那个IP>:8787/hunan.m3u
```

要央视 + 卫视 + 湖南全都在一个列表里，就填 `.../aptv.m3u`。
名字随便起（建议写「家里湖南」），保存后等它自己拉取，成功后会出分组：
📍 湖南本地 / 长沙 / 市州 / 金鹰 等。

## 加不上时按这个顺序查

| 现象 | 说明什么 | 怎么处理 |
| --- | --- | --- |
| 手机打开 `http://<窗口里的IP>:8787/` 也转圈/拒绝连接 | 电脑根本连不上，跟 APTV 无关 | 看下一条 |
| 手机能打开，Apple TV 打不开 | 电视和电脑不在同一网段，或路由器开了「无线隔离 / 访客网络」 | 见下面「网段」一节 |
| 服务窗口里**一行都没跳出来** | 请求根本没到电脑，100% 是网络层问题 | 同上，别再改 APTV |
| 窗口里跳出了 `★ 有别的设备连上来了：192.168.x.x` 但 APTV 还是报错 | 网络通了，问题在 APTV 输入或 tvOS 侧 | 按下面「换诊断表」的顺序试 |
| 订阅成功，但台点开是超时 | 分两种：这条线路在**看电视的那个网络**里够不到，或这个台只有运营商内网线路 | 见下面「播不动怎么判」一节 |

### 播不动怎么判：先看 `data/output/report.md`

生成时已经按「电视能不能连上」把线路分成三档，写在 `report.md` 的
「线路的可达范围」一节里：

| 档 | 含义 | 电视上的表现 |
|---|---|---|
| 公网 | 走公共 CDN、广电官方分发、机房中转 | 通了才能播；2026-09-21 起同一档内再按实测延迟分先后 |
| 运营商 IPTV 内网 | 移动/联通的 IPTV 专网地址（`tvgslb.hn.chinamobile.com`、`58.20.64.92` 这类） | 家庭 Wi-Fi 上**从没被证明能通**（这一档在电脑上**一个请求都没发过**，见下面那条），预期是超时，真答不答案要在电视上点 |
| 纯音频电台 | 上游把电台地址挂在电视频道名下 | 点开只有声音，已排到最后 |

> 从这一段起，有些数字后面挂着 `〔数:aptv:suspect〕` 这种东西。那是给我看的记号，
> 意思是「这个数出自哪张表的哪一个量，一条命令就能重算：`./.venv/bin/python -X utf8 scripts/doc_num.py`」
> —— 表换过一轮，忘了重抄的地方会自己跳出来（计划书 2.28）。**读的时候直接跳过。**

**「实测」这两个字盖不住全部 226〔数:aptv:lines〕 条线。** 现在这张表里 167〔数:aptv:public-lines〕 条是公网线路、
每一条都有 21:18 那轮的逐条通过记录；另外 **59**〔数:aptv:intranet-lines〕 条是运营商内网那一档，
电脑侧对它们没做过任何测量（`hn_unicom`、`hn_mobile`
这两个源在 `config/sources.yaml` 里标了 `probe: false`，因为它们十有八九连不上，测了只会白等超时）。
所以这 59 条在 Wi-Fi 上的表现是**推出来的、不是量出来的**。

**这一档有多要紧，现在是算出来的（计划书 2.23；`report.md` 的「第一线主机集中度」那一节 ——
2.23 之后生成的那份才有，眼下躺在 `data/output/` 里这份还没有，见下面「怎么看到它」那条）。**
全量那 98〔数:aptv:channels〕 个台的第一线只落在 20〔数:aptv:focus-hosts〕 家主机上，
而集中度最高的两家恰好就是这 59〔数:aptv:intranet-lines〕 条所在的专网出口：

| 第一线主机 | 挂着几个台 | 其中「换线路也换不出去」的 | 出自哪个源 |
|---|---|---|---|
| `tvgslb.hn.chinamobile.com:8089` | 22〔数:aptv:focus:tvgslb.hn.chinamobile.com〕（湖南表里 20〔数:hunan:focus:tvgslb.hn.chinamobile.com〕） | **22 个全部** | `hn_mobile`（湖南移动 IPTV） |
| `58.20.64.92:9999` | 17〔数:aptv:focus:58.20.64.92〕（湖南表里 17〔数:hunan:focus:58.20.64.92〕） | 3 | `hn_unicom`（湖南联通 IPTV） |

`58.20.64.92` 长得像一个公网 IP，登记的却是湖南联通的 IPTV 出口，而你家的宽带恰好就是联通 ——
它挂着的 17〔数:aptv:focus:58.20.64.92〕 个台是：湖南经视、湖南都市、湖南娱乐、湖南电视剧、湖南电影、湖南教育、湖南公共、
金鹰卡通、金鹰纪实、长沙新闻综合、长沙女性、张家界新闻综合、张家界公共、怀化新闻综合、
湘西新闻综合、湘西文化旅游、常德公共。

移动那 22〔数:aptv:focus:tvgslb.hn.chinamobile.com〕 个更干脆：**它们名下所有线路都在 `tvgslb` 这一台上**（湖南表里的 20〔数:hunan:focus:tvgslb.hn.chinamobile.com〕 个 = 市州台为主，
例：湖南国际、湖南爱晚、长沙政法、娄底公共），所以在电视上切第 2、第 3 条线路也换不出别的家。
两家合起来就是湖南表 39〔数:hunan:channels〕 个台里的 37〔数:hunan:suspect〕 个。

**「那换第二条线路呢」现在也是同一节算出来的（计划书 2.26）**：第一线可疑的 39〔数:aptv:suspect〕 个台里
24〔数:aptv:no-alt〕 个连一条备选线路都没有、1 个的备选还在同一家机房、14 个换过去仍是专网出口、
**0〔数:aptv:other-public〕 个换得到公网电视线路**（湖南表 37〔数:hunan:suspect〕 个 → 22/1/14/**0**〔数:hunan:other-public〕）。
所以别在电视上靠切线路救这批台 —— 那一步省下来。

**这两个端口在电视上只被判过一次分**：改排序之前那轮，`hunan.m3u` 的 39/39 个台第一条线路都是
专网地址，真机上的观感是整张表全超时（计划书 2.8）。所以现在「点开它们」的先验是**不通**，
这一次点是为了确认，不是为了发现 —— 万一有一台出画了，那是把 20〔数:hunan:focus:tvgslb.hn.chinamobile.com〕 或 17〔数:hunan:focus:58.20.64.92〕 个台一次性捞回来的大新闻，
值得单独告诉我一句。

**每个频道的公网线路已经排在第一条**，因为 APTV 默认只播第一条。所以：

- 报告里「一条公网线路都没有的 N 个频道」那一串，就是**在 Wi-Fi 上不用试**的台。
  2026-09-21 已经把这批台能走的公网路子穷尽查过一轮（见计划书 2.12）：**台方自己的公网裸流基本不存在**，
  有流的几家（娄底、新湖南平台）都在 IP 白名单后面。要看这些台，实际只剩 IPTV 机顶盒 HDMI，
  或者去抓各市州融媒 App 的包补进 `config/sources_local.yaml`。
- 反过来，**报告里没被点名的台播不动**，就是那条公网线路本身失效了，
  属于「源会老化」这一类，重跑一次生成即可。

跑过 `build --verify` 之后还有两栏可以直接对账（这台 Mac 和电视同一个 Wi-Fi、
同一条宽带出口，关掉代理的 TUN 时测出来的就是电视的结果）：

- **「实测逐主机」表**：整族失效的主机（比如 `stream1.freetv.fun` 0/35）意味着挂在它名下的
  「公网线路」等于不存在 —— 这些台会出现在上面那一串里，不用真机再确认一遍。
- **「按上游源摊开」一节**：同一批结论按 `config/sources.yaml` 里的源各摊一遍，
  末尾给一段能直接抄的 `priority:` / `enabled:` —— 但**它只是建议，代码不会自己改那个文件**。
  一道门槛拦着它乱开价：只看过一轮的源一律「先看一轮，先别动」，
  只挂过一两条线路的源不许被建议整源关掉（可逆的降档可以，不可逆的不行）。
  源自己老化时（某一路聚合源整批撤线），这一节是最先该看的地方。
- **`probe.json`**：本轮实测的快照，逐条线路的结果和出口身份。怀疑某个数字是怎么来的，看它的 `egress` 那行。
  每条线路还带一个 `kind`：`live` 真直播列表、`master` 多码率索引（跟一跳看变体）、
  `vod` 循环录像（挂在频道名下就是假直播，已经被排到真直播后面）、`raw` 裸 `.ts` 直链。
  2.20 起它还是 `build --replay` 的输入 —— 那份逐条判决可以整个拿来当「本轮结果」重出表，
  于是换配置不必再等一次干净出口（详见下面「重跑一次可信实测」那一节和计划书 2.20）。
- **`untrusted/`**：体检报警的那些轮（代理 TUN 开着、出口在境外机房）的产物会整个写到这个子目录里，
  `data/output/` 保持上一轮可信版本。原因是 `--verify` 会**删**掉它认为连不上的线路，
  而局域网服务正把 `data/output/` 当订阅目录发给电视 —— 一轮假阴性不该把电视正在用的那张表换掉。
  看到终端里那行「体检报警的这一轮不碰订阅目录」就是这个机制在起作用；
  确实要在别的测量点上出表就加 `--allow-untrusted`。
- **`probe-history.jsonl`**：上面这些轮次的履历（一行一轮，30 分钟内连跑算同一轮）。
  它解决的是「这次没实测」的场合：不带 `--verify` 重跑一次 `build`，
  排序会照履历走 —— 上一轮整族连不上的主机往后压，上一轮量到 378ms 的那条官方流顶上第一线。
  没有它的时候，离线重出一次表就能把最好的线路挤没了（计划书 2.13 记了那次回归）。
  除了「连不连得上」，履历里还记**「连上了放出来的是什么」**：某一族里通了的线路全是循环录像，
  下次离线重出表它照样往后压；L3 隔间隔验过「分片窗口一动不动」的那一条也会单独往后压。
  只有**体检没报警**的那些轮参与判断，出口在境外机房的轮次会被记下但不用。
  每行还记 `srcs`：这一族是哪些上游塞进来的 —— 没有它就只能说「这族全灭」，说不出该动哪一行。
  2.17 之前那几轮的这个字段是 `scripts/backfill_srcs.py` 事后按同一份上游缓存补记的
  （来历写在每轮的 `srcs_note` 里，对不上出处的留空不猜；能播几条那些数字仍是当时实测的）。
  体检现在是两条独立证据：DNS 有没有落进 fake-IP 段、出口身份里的国家码是不是 CN ——
  代理不接管 DNS 时前一条全绿，后一条才兜得住（2026-09-21 夜补的，见计划书 2.16）。

### 先说清楚：现在这版在 Wi-Fi 上能播的就 2 个台

2026-09-21 在**和电视同一张网**的电脑上实测，`hunan.m3u` 39 个频道里只有 2 个台的第一线连得上，
并且都用「隔 20 秒重取、看分片窗口有没有往前走」验过是真直播不是循环录像：

| 台 | 第一线是什么 | 电脑实测 |
|---|---|---|
| 湖南卫视 | 湖南广电官方公网流 `hlsal-ldvt.qing.mgtv.com` | 190ms，分片滚动 |
| 湘潭新闻综合 | 湘潭广电自建 `live.hnxttv.com:9601` | 47ms，分片滚动 |

其余 37〔数:hunan:first-intranet〕 个台（湖南经视、都市、娱乐、长沙各套、各市州台、金鹰系）**只剩运营商 IPTV 专网地址**，
在 Wi-Fi 上点开必然转圈。所以真机验收要看的不是「39〔数:hunan:channels〕 个台能不能播」，而是这三件事：
① 上面这 2 个台在电视上出不出画、撑不撑得住；② 被点名的那 37 个是不是真的全都超时
（万一有个别能播，说明你这条宽带进得去 IPTV 专网，解法要整个重写）；
③ `probe-pack.m3u` 里电视能动哪几个编号（带 ★ 的那两条官方流是要重点看的：
⑬ 湖南广电、⑭ 湘潭广电；编号会随表浮动，认 ★ 不认编号）。

`aptv.m3u` 那侧刚多了 6 个台（计划书 2.14）：**CCTV-5+赛事 从 CCTV-5体育 里拆出来了** ——
之前点「CCTV-5体育」有三条线路里一条其实是赛事频道的地址，看到的就是另一套节目；
另外补进 5 个上游本来就有公网线路、却因挂在外省分组而被丢掉的上星频道
（厦门、福建海峡、大湾区、延边、安多卫视）。**湖南这 39〔数:hunan:channels〕 个台的表一个字节都没变**，
上面那 2 + 37 的结论照旧，真机验收不用为此改流程。

重跑一次可信实测的命令（代理客户端的 TUN 要先关掉，屏幕上三行体检警告消失才算干净）：

```
.venv/bin/python -m src.cli build --verify

# 不联网测：把 probe.json 那批逐条判决当本轮结果用（换配置、换节目单时不必等干净出口）
.venv/bin/python -m src.cli build --replay

# 单独验某几个台的第一线是不是真在滚动（L3，每次要多等几十秒）：
.venv/bin/python scripts/verify_lines.py data/output/hunan.m3u --roll 20

# 同上，但把结论写进履历，以后离线重出表也认（`--to-history`）：
.venv/bin/python scripts/verify_lines.py data/output/hunan.m3u --roll 20 --to-history
```

三种「重跑一次」不是一回事，挑错了会白等：

| 命令 | 线路判决从哪来 | 会动什么 | 什么时候用 |
|---|---|---|---|
| `build --verify` | 本轮当场测（350 条线路逐条下判决） | 表 + 报告 + `probe.json` + 履历 | 要知道线路**现在**通不通；必须家里出口、体检干净 |
| `build --replay` | 上一轮那份 `probe.json`（**线路**一条都不测；节目单那一格例外 —— 缓存里没有今天就会重取一次，要真一个请求都不发就再加 `--no-epg`） | 只动表和报告，**不写** `probe.json`、不追加履历 | 改了配置／节目单，想在同一批判决上看表长成什么样 |
| `build`（都不带） | 没有判决，只有履历里的判据 | 动表，且**不删**失效线路 | 只是想看离线版长什么样；给电视用之前别拿它覆盖 `data/output/` |

`--replay` 有三道门，撞上了会直接拒绝而不是出表：那一轮体检报过警、它的出口跟本轮参照出口不是一个、
记录太旧（默认 48 小时，`--replay-max-age` 可调）。这三道各对应一次真翻过的车，
所以别一上来就加 `--allow-untrusted`。它跟 `--verify` 同时给也会被立刻拦下。

`--to-history` 只在**同一个出口**下才写得进去：TUN 开着跑 L3，「列表不动」更可能是隧道掐了
而不是源停了，脚本会直接拒绝回写并说明原因（履历文件一个字节都不动）。
还有个小坑：30 分钟内再跑一次 `build --verify` 会把那一轮整行替换掉，顺带把 L3 的结论清空 ——
顺序是「先 `--verify`，再 L3 回填」，反过来做等于白验。

### 节目单（EPG）显不显示，是另一件事

2026-09-21 深夜起，订阅表头部那行 `x-tvg-url` 不再是从上游抄来的了（抄的那条实测 404，
电视取节目单第一步就失败），改成自己填的一份，写在 `config/epg.yaml`。同一轮里
每个频道的 `tvg-id` 也不再由上游到达顺序决定，而是**由这份节目单里到底有哪个 id 反推**。

在电视上判它通没通，就是点开一个台看有没有节目条：

| 该有节目的样子 | 对照（**故意没有**） |
|---|---|
| 湖南卫视、湖南经视/都市/娱乐/电影/电视剧/国际/爱晚、金鹰卡通、金鹰纪实 | 湘潭新闻综合、长沙政法、株洲新闻综合 |
| CCTV 全系（`CCTV-1综合` 到 `CCTV-17农业农村`）、CETV | 湖南公共、湖南教育 |
| 广东卫视、北京卫视等上星台 | 其余市州地面台 |

全量表里 99 个台有 70 个能配上，湖南那张 39 个台里只有 10 个 —— 剩下那些市州台
在境内公开节目单里根本不存在（不是写法对不上，是名单里没有），所以它们没有节目条是**正常**的。
（拿现在电视上那张 98〔数:aptv:channels〕 个台的实测表去量是 **69**：差的那一个台是 `香港卫视`，它 21:18 那轮
三条线路全失败（一条 403、两条 12 秒超时）所以整台被删了，跟节目单没关系。
两个数不是矛盾，`.venv/bin/python scripts/epg_check.py --playlist <哪张表>` 自己重量一遍就有。）

几点先说在前面：

- **眼下电视上那张表还没有这一层**：`data/output/` 里是 21:18 那轮实测表，头部仍是老的 404 那条。
  这一层在**下一次生成**时才生效。以前这句意味着「等一次家里的干净出口跑 `build --verify`」，
  2.20 之后不用等：`build --replay` 拿 21:18 那份逐条判决重出，线路一条不会变
  （关掉节目单时四张表与 `data/output/` 逐字节相同，验过），只多这一行头部和换成数字的 `tvg-id`。
  要不要现在就换这一张，是要说一声的（它动的是电视正在读的那份）。
  **这句话现在可以自己验，不用问我、也不用联网**：`./.venv/bin/python scripts/epg_check.py data/cache/epg.xml`
  —— 它把「按 `tvg-id` 配上几个」和「靠台名救回几个」分开印，再印一行「这张表的来历」。
  眼下那张表给的是 `0 按 id + 69 靠台名`、来历那句是「没有一个 id 来自这一份节目单」；
  等这张表换成带这一层的那版，那行会自己变成「id 就是这一份节目单那一套」。
- 换了节目单，`tvg-id` 会整列跟着换（会变成 `81`、`11` 这种数字）。**台名不受影响**
  —— 电视上看到的名字来自 `tvg-name`，那是中文，一直是我们的标准名。
  会换多少个台是量出来的：现在给电视那张表 98〔数:aptv:channels〕 个台里 **69 个**会换，湖南那张 39〔数:hunan:channels〕 个里只有 **10 个**。
  `tvg-id` 在 APTV 里是频道的身份，收藏／隐藏可能挂在它上面 ——
  **所以换新表之前先在 APTV 里收一两个台**（收一个会换 id 的，比如湖南卫视；再收一个不会换的，比如某个市州台），
  换完再看收藏还在不在。掉了就告诉我，那说明这一层要加一条「id 第一次生效之后就按台名钉住」的规则，
  这不是不能改的事，只是得先看一次真实行为。
  （钉住有一个反面代价，2026-09-22 量过之后才看清楚：id 一旦钉在 erw 的那套数字上，
  以后再换任何一份节目单都配不上了 —— 所以这条规则要不要加，取决于「收藏掉了」和
  「以后还想不想换节目单」哪个更要紧。）
- 上面说该有节目条的那两个台（湖南卫视、CCTV-13新闻）**也不出**节目条 → 最可能是家里那张 Wi-Fi 取不到这个地址。做法是把
  `config/epg.yaml` 里 `url:` 换成下面那行 `backup_url:` 的值（另一个境内服务），重跑一次生成再试
  （2.20 之后这一步不用等干净出口：`build --replay` 就够，线路一条不会变）。
  **但这一退不免费**：净少配 8 个台（它缺 9 个 —— CETV 全系、`CCTV-1综合`、`安多卫视`、`湖南都市`、
  金鹰卡通／纪实，只多出一个 `长沙政法`），每次电视要多拉 3.0MB 未压缩的 XML，
  而且它给同样那些台的 id 跟 erw **全都不一样** —— 从 erw 版退过去等于 98〔数:aptv:channels〕 个台里 69 个的 id 再换一遍、
  收藏再冒一次风险。所以顺序是：**先确认 erw 那个域名在家里到底通不通**（手机连同一个 Wi-Fi 打开
  `https://e.erw.cc/e.xml.gz` 看一眼就行），确认不通再换，别顺手换。
  或者整个关掉 `enabled: false`，回到「不显示节目单、但线路一切照旧」。**不要为了这个去动代理**。
- 节目单只给**今天**，不给明天（2026-09-22 这份 18147 条里 17833 条是今天的、09-23 一条都没有；
  昨天那份是 18359 条里 18046 条）。
  所以缓存每天会自己过期重取，隔天第一次生成可能要联网，几秒钟。

### 网段怎么对

Apple TV：**设置 → 网络 → （当前网络）→ 看 IP 地址**。
电脑：服务窗口里打印的那个 IP。
两边前三段必须一样。

- 两边都是 `192.168.1.x`（或都是 `192.168.31.x`）→ 填电脑那个 IP
- 电视是别的段（例如电脑 `192.168.31.87`、电视 `192.168.1.x`）→ **电脑连的是另一个
  Wi-Fi**（家里挂了二级路由、副 AP 或访客网络）。这种情况下电脑放不出订阅，
  要么让电脑去连电视所在的那个 Wi-Fi，要么把服务搬到 NAS 上常驻（P4）。
  路由器如果开了「无线隔离 / AP Isolation / 访客网络隔离」，也要关掉。
